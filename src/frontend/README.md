# Frontend — Pass'on

*[English](#english) · [Français](#français)*

---

## English

Pass'on's interface: **React + JavaScript**, built by **Vite**, using La Suite
Numérique's design system (`@gouvfr-lasuite/ui-components`).

**No TypeScript**: everything is `.jsx`/`.js`, by explicit request (see
`PLAN.md`). The original README, generated by the Vite template, said the
opposite.

### Running it

In development, the Vite server with hot reload on **http://localhost:5173**
(`/api` is proxied to :8090, so a real login works from here):

```bash
npm install
npm run dev
```

With the rest of the stack (nginx + Django behind one port,
**http://localhost:8090**), from the repository root:

```bash
make up
```

In that second mode the app is compiled into the Docker image: a frontend change
only shows after another `make up`. For interface work, use `npm run dev`. See
[`src/server/README.md`](../server/README.md).

### Available commands

| Command | Effect |
| --- | --- |
| `npm run dev` | development server (hot reload) |
| `npm run build` | compiles the app into `dist/` — what nginx serves |
| `npm run preview` | serves `dist/` to check a build |
| `npm run lint` | analyses the code with [Oxlint](https://oxc.rs) |

The rules live in `.oxlintrc.json`. On top of the defaults:
`no-use-before-define` (a constant read before its declaration raises a
`ReferenceError` during render: the screen goes blank, with no message),
`react/rules-of-hooks` and `no-unused-vars`. See the
[rules documentation](https://oxc.rs/docs/guide/usage/linter/rules).

`oxlint` is not always installed locally; failing that:

```bash
docker run --rm -v "$PWD":/work -w /work node:22-alpine npx oxlint@1.81.0 src
```

### Where to read next

- **`PLAN.md`** — the product scope: what is done, what is left, and the
  decisions taken along the way.
- **`DOCUMENTATION.md`** — how the code is built, file by file: the routes, the
  Contexts (authentication, handovers, theme), where data comes from, what
  belongs to the design system and what was written by hand.

### Worth knowing about the dependencies

`package.json` carries an `overrides` field pinning a single version of
`react-aria` and `react-stately`. It is not decorative: without it, the design
system's ~47 `@react-aria/*` sub-packages each install their own full copy of
those libraries, and `node_modules` goes from 375 MB to 2.9 GB. The detail is at
the end of `DOCUMENTATION.md`.

## Français

Interface de Pass‘on : **React + JavaScript**, compilée par **Vite**, avec le
design system de la Suite Numérique (`@gouvfr-lasuite/ui-components`).

**Pas de TypeScript** : tout est en `.jsx`/`.js`, sur demande explicite
(voir `PLAN.md`). Le README d'origine, généré par le template Vite, annonçait
l'inverse.

### Lancer le projet

En développement, serveur Vite avec rechargement à chaud sur
**http://localhost:5173** (données mockées, backend non nécessaire) :

```bash
npm install
npm run dev
```

Avec le reste de la pile (nginx + Django sur un seul port,
**http://localhost:8090**), depuis la racine du dépôt :

```bash
make up
```

Dans ce second mode l'appli est compilée dans l'image Docker : une modification
du front n'apparaît qu'après un nouveau `make up`. Pour travailler sur
l'interface, utilise `npm run dev`. Voir
[`src/server/README.md`](../server/README.md).

### Commandes disponibles

| Commande | Effet |
| --- | --- |
| `npm run dev` | serveur de développement (rechargement à chaud) |
| `npm run build` | compile l'appli dans `dist/` — c'est ce que sert nginx |
| `npm run preview` | sert le contenu de `dist/` pour vérifier une compilation |
| `npm run lint` | analyse le code avec [Oxlint](https://oxc.rs) |

Les règles sont dans `.oxlintrc.json`. Aux règles par défaut s'ajoutent
`no-use-before-define` (une constante lue avant sa déclaration lève une
`ReferenceError` au rendu : l'écran devient blanc, sans message),
`react/rules-of-hooks` et `no-unused-vars`. Voir la
[documentation des règles](https://oxc.rs/docs/guide/usage/linter/rules).

`oxlint` n'est pas toujours installé localement ; à défaut :

```bash
docker run --rm -v "$PWD":/work -w /work node:22-alpine npx oxlint@1.81.0 src
```

### Où lire la suite

### À savoir sur les dépendances

`package.json` contient un champ `overrides` qui force une version unique de
`react-aria` et `react-stately`. Ce n'est pas décoratif : sans lui, les ~47
sous-paquets `@react-aria/*` du kit installent chacun leur propre copie
complète de ces librairies, et `node_modules` passe de 375 Mo à 2,9 Go. Le
